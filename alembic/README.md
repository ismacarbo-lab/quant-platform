Alembic is configured against PostgreSQL via `Settings.database_url`.

Phase 0 / 0.1 has no financial schema, so there are no domain revisions in
`versions/` yet. Runtime verification:

```bash
docker compose up -d postgres
uv run alembic current
uv run alembic upgrade head
uv run python scripts/check-db.py
```

`alembic current` reports the applied revision (empty until the first real
migration). `alembic upgrade head` with no revisions must not create market,
signal, or order tables. Alembic may create the infrastructure table
`alembic_version` only.

When a model is added to `quant_platform.storage` (or another module that
registers on `Base.metadata`):

```bash
docker compose up -d postgres
uv run alembic revision --autogenerate -m "describe the change"
uv run alembic upgrade head
```

Always review autogenerated revisions before applying them.

Do not point Alembic at SQLite. `Settings` rejects non-PostgreSQL URLs.

Stop the database with `docker compose down`.
